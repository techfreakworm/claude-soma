LinkedIn is DIFFERENT. The OLD architecture (social-manager's warm
playwright-linkedin MCP session, kept alive in the responsive lead

ephemeral headless context gets flagged with /checkpoint/challenge

So: for LinkedIn, you DO NOT call browse-linkedin.js. Instead, you
send a `mcp__project-orchestrator__send_to_project` call to
social-manager asking it to do the LI browse+draft pass with its
warm session. social-manager appends LI drafts to queue.jsonl on
its own cadence; the dispatcher's hourly drip pops one LI from the
pool. LI drafts may be 30-90 min stale by the time they land in
pending_review — that's accepted, the user signed off.

Use the X harvest helper via the Bash tool. It loads the same
storageState the post scripts use and sees the real logged-in feed.

  X harvest:
    node /opt/claude-soma/scripts/engagement-browse-x.js --n 25

The script streams one JSON line per harvested post to stdout, followed
by a single RESULT line. The RESULT line is one of:

  RESULT:OK n=<count> auth=<bool> url=<final-url>
  RESULT:NEEDS_REAUTH url=<final-url>        — storageState rejected /
                                                login wall. The operator
                                                must re-run pw-login on
                                                the VNC desktop. Emit
                                                zero drafts for that
                                                platform and continue.
  RESULT:ERROR <message>                     — anything else; emit zero
                                                drafts for that platform.

Each JSON line has the shape (engagement.v1 schema —
docs/engagement-schema.md is the single source of truth):

  {
    "platform": "x" | "linkedin",
    "source_author": "@handle or Firstname Lastname",
    "source_permalink": "https://...",
    "source_excerpt": "<first ~280 chars of the post>"
  }

NOTE: the field is `source_permalink` (NOT `source_post_url`). Use the
exact field name `source_permalink` in your queue.jsonl appends below —
the post helper script `engagement-post-x.js` / `engagement-post-li.js`
looks up the URL by that exact key. A null/missing permalink makes the
draft un-postable.

NOTE 2: as of engagement.v1 (2026-06-06) the excerpt field is
`source_excerpt`. The legacy name `source_post_excerpt` is renamed.
The renderer still reads the legacy name for one schema version, but
producers MUST emit `source_excerpt`.

Workflow:

  1. Run the X harvest. Capture stdout to a temp file (e.g. /tmp/eng-x.jsonl).
     Read the file. If the last line is `RESULT:OK n=<n>` with n>0, great.
     If `RESULT:NEEDS_REAUTH` or `RESULT:ERROR ...`, emit zero X drafts and
     proceed to step 4 anyway (so the LinkedIn delegation still fires).
     Do not retry the X harvest.
  2. From the harvested X posts (skip the RESULT line), pick 3-5 that are
     worth a genuine comment. Skip:
     - retweets / reposts with no original content
     - posts already swamped with replies
     - low-quality engagement-bait
     - controversial framings that don't fit the operator's voice
  3. For each pick, draft a 1-3 sentence humanized comment in the
     operator's voice: terse, technical, no emoji, no "great post!"
     filler. Add a concrete observation, a related anecdote, or a sharp
     question. Do not just agree.
  4. Append each X draft as a single JSON line to __QUEUE_PATH__ in
     ENGAGEMENT.V1 schema (docs/engagement-schema.md is canonical):

     {
       "schema_version": "engagement.v1",
       "id": "eng-x-<6hex>",
       "platform": "x",
       "status": "queued",
       "queued_at": <unix-epoch-int>,
       "freshly_drafted_at": __START_TS__,
       "source_author": "<from harvest>",
       "source_permalink": "<from harvest — REQUIRED, never null>",
       "source_excerpt": "<from harvest>",

       "topic": "<one of: claude-code|agents|mcp|infra|dev-tooling|ai-research|voice|other>",
       "relevance_note": "",

     Use Bash to append one line at a time:
       printf '%s\n' '<the json>' >> __QUEUE_PATH__
     Generate the hex with `openssl rand -hex 3`.

On exit
============================================================

Print a single status line as your final stdout, format:

  ENGAGEMENT-DRAFTS x=<n> linkedin=delegated errors=<short-text-or-none>

`linkedin=delegated` means you sent the refill request to social-manager
and exited; the actual LI draft count lands in the queue
asynchronously and is counted by the dispatcher at drip-time, not by
you. If the send_to_project call ITSELF failed (social-manager not
running, MCP error), report it as `linkedin=delegation-error: <reason>`
so the operator sees the signal.

Then stop. The dispatcher inspects the queue file directly to determine
how many fresh drafts landed; the status line is for the operator log.
